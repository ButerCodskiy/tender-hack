# Дорожная карта разработки платформы на хакатоне

Документ представляет собой единый план реализации системы для распределенной команды из четырех инженеров. Дорожная карта разбита на три уровня приоритетов, содержит интерактивные отметки выполнения задач и фиксирует регламенты бесконфликтной совместной работы над кодовой базой.

---

## 1. Регламент предотвращения конфликтов слияния

Для исключения блокировок и конфликтов при слиянии веток команда руководствуется следующими правилами:

1. **Строгая изоляция зон ответственности:**
   * Каждый инженер создает, изменяет и тестирует код исключительно в закрепленных за ним каталогах.
   * Прямые правки чужих модулей запрещены. Любые доработки оформляются в виде запроса к ответственному разработчику.
2. **Разработка от контрактов и сервисные заглушки:**
   * Межмодульное взаимодействие строится через утвержденные структуры данных Pydantic из спецификации [API_SPECIFICATION.md](API_SPECIFICATION.md).
   * Если модуль смежного исполнителя еще не готов, вызывающая сторона реализует локальную сервисную заглушку с утвержденной сигнатурой метода. После завершения смежного модуля заглушка бесшовно заменяется боевой реализацией без изменения внешних контрактов.
3. **Фиксация изменений интерфейсов:**
   * Любое изменение согласованных схем Pydantic, параметров вызова сервисов или эндпоинтов предварительно оформляется архитектурной записью в каталоге [docs/adr/](adr/).
4. **Закрепление общих точек сборки:**
   * Сборка и подключение доменных роутеров в файлах [main.py](../backend/src/main.py) и [router.py](../backend/src/api/v1/router.py) закреплены строго за **Разработчиком 4**. Другие разработчики экспортируют роутеры из своих модулей.
   * Формирование, выравнивание и накат общих миграций базы данных через инструмент Alembic закреплены строго за **Разработчиком 4**. Разработчики 1, 2 и 3 передают готовые декларативные модели ORM без самостоятельного создания файлов миграций.
