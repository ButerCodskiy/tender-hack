# Установка инженерных навыков и первичная настройка репозитория

Настоящее руководство описывает процесс загрузки инженерных навыков Мэтта Покока и пошаговое выполнение команды `/setup-matt-pocock-skills` для приведения репозитория к единому стандарту разработки.

---

## 1. Загрузка навыков

В современной экосистеме навыки распространяются через открытый реестр `skills.sh` либо подключаются как управляемые расширения.

### Основной вариант: Установка через менеджер навыков

Команда выполняется в корне репозитория:

```bash
npx skills@latest add mattpocock/skills
```

Порядок действий в интерактивном установщике:
1. Выбрать среду выполнения. Для Antigravity целевым каталогом является `.agents/skills/`.
2. Отметить необходимые навыки. Обязательно выбрать инициализирующий навык `setup-matt-pocock-skills`, а также ключевые инструменты инженерного процесса:
   - `wayfinder` — декомпозиция крупных задач и построение карты решений;
   - `to-spec` — фиксация спецификаций и интерфейсных швов;
   - `to-tickets` — нарезка спецификации на независимые задачи;
   - `implement` — реализация задач по методологии разработки через тестирование;
   - `code-review` — двухосевая проверка кода перед слиянием;
   - `resolving-merge-conflicts` — интеллектуальное разрешение конфликтов слияния;
   - `diagnosing-bugs` — строгий протокол локализации и устранения дефектов;
   - `grill-with-docs` — выравнивание требований и ведение контекстной документации.

### Альтернативные варианты

1. **Для Claude Code:**
   Установка плагина через консоль:
   ```bash
   claude plugins install mattpocock-skills
   ```
   Либо вызов внутри сессии: `/plugin install mattpocock-skills`.

2. **Локальное размещение файлов:**
   Если файлы навыков уже присутствуют в проекте, директории с `SKILL.md` помещаются напрямую в `.agents/skills/<имя_навыка>/` (на уровне репозитория) либо в глобальный каталог конфигурации пользователя `~/.gemini/config/skills/`.

---

## 2. Выполнение команды `/setup-matt-pocock-skills`

Команда вызывается разработчиком вручную в начале работы с репозиторием:

```text
/setup-matt-pocock-skills
```

### Назначение команды

Навык выполняет первичный аудит репозитория и настраивает общие правила взаимодействия для всех остальных инструментов. Сами исполняемые навыки универсальны и неизменны, а специфика конкретного проекта фиксируется в создаваемых файлах конфигурации.

### Ключевые решения и рекомендуемый выбор

В процессе диалога агент анализирует проект и запрашивает подтверждение трех параметров. Для архитектуры нашего проекта установлены следующие параметры:

1. **Трекер задач (Issue Tracker)**
   - **Выбор:** Локальные файлы Markdown (`Local Markdown`).
   - **Расположение задач:** каталог `.scratch/<название_фичи>/issues/`.
   - **Обоснование:** задачи изолируются внутри ветки функционала, не требуют внешних сетевых доступов и сохраняются в истории контроля версий вместе с кодом.

2. **Словарь меток классификации (Triage labels)**
   - **Выбор:** Использовать стандартный набор из пяти канонических ролей:
     - `needs-triage` — новая задача, требующая первичной оценки;
     - `needs-info` — недостаточно входных данных;
     - `ready-for-agent` — задача полностью декомпозирована и готова к исполнению агентом;
     - `ready-for-human` — требуется решение или действие со стороны инженера;
     - `wontfix` — отклоненная задача.

3. **Структура доменной документации (Domain documentation)**
   - **Выбор:** Многоконтекстная модель (`multi-context`).
   - **Структура:** единая карта контекстов `CONTEXT-MAP.md` в корне, локальные файлы `CONTEXT.md` внутри доменных пакетов сервиса (например, `src/auth/`, `src/documents/`) и каталог архитектурных решений `docs/adr/`.
   - **Обоснование:** бэкенд разбит на функциональные подсистемы со своей специфичной терминологией, моделями данных и очередями.

## 3. Результаты работы команды

После завершения диалога в проекте формируются следующие артефакты:

1. `docs/agents/issue-tracker.md`
   Содержит регламент ведения задач: формат описания, правила нумерации, учет взаимных блокировок и алгоритм построения карт решений.
2. `docs/agents/domain.md`
   Определяет правила маршрутизации к локальным контекстным файлам через карту `CONTEXT-MAP.md` и регламент оформления записей архитектурных решений.
3. `docs/agents/triage-labels.md`
   Таблица соответствия проектных меток стандартным ролям (создается при наличии навыка сортировки задач).
4. Раздел в файле `AGENTS.md`
   В корневой файл инструкций агента добавляется секция `## Agent skills` со ссылками на созданные файлы конфигурации, благодаря чему последующие команды работают автономно.

---

## 4. Практические нюансы

- **Ручной запуск:** Навык намеренно защищен от автоматического вызова другими агентами. Инициализацию всегда запускает разработчик.
- **Однократность:** Повторный вызов команды требуется только при кардинальной смене инфраструктуры, например при переходе с локального Markdown на внешний трекер задач.
- **Неделимость выбора:** При использовании локального Markdown файлы задач ведутся исключительно в `.scratch/`. Смешивать локальный трекер с внешними системами в рамках одного репозитория не рекомендуется.
- **Связь с остальными командами:** После завершения начальной настройки команды `/to-spec`, `/to-tickets`, `/wayfinder` и `/implement` считывают пути из `docs/agents/` и больше не запрашивают контекст размещения артефактов.
