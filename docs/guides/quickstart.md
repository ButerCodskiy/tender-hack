# Руководство по быстрому старту для разработчиков

Инструкция по развертыванию локального окружения бэкенда, работе с менеджером пакетов и настройке автоматических проверок перед фиксацией изменений.

---

## 1. Установка менеджера пакетов `uv`

В проекте используется `uv`. Он управляет версиями языка, зависимостями и виртуальными окружениями без необходимости вручную настраивать среды.

### Установка в Windows (PowerShell)
Выполните в терминале PowerShell:
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

*Альтернативно через диспетчер пакетов Windows:*
```powershell
winget install --id=astral-sh.uv -e
```

После установки перезапустите терминал и убедитесь, что утилита доступна:
```powershell
uv --version
```


---

## 2. Развертывание зависимостей бэкенда

Перейдите в каталог бэкенда:
```bash
cd backend
```

Синхронизируйте проект. Команда автоматически создаст локальное виртуальное окружение `.venv` и установит все основные и тестовые библиотеки строго по зафиксированным версиям:
```bash
uv sync
```

---

## 3. Активация хуков системы контроля версий

Для поддержания единого стиля и чистоты кода в репозитории настроены автоматические проверки линтером и форматирование перед каждым коммитом.

Находясь в каталоге `backend`, выполните:
```bash
uv run pre-commit install
```

Команда свяжет файл конфигурации `.pre-commit-config.yaml` из корня репозитория с хуками Git.

### Проверка работоспособности
Чтобы убедиться, что проверки работают, запустите их вручную по всем существующим файлам:
```bash
uv run pre-commit run --all-files
```
Все проверки должны завершиться со статусом `Passed`.

---

## 4. Запуск локальной инфраструктуры

В корне проекта поднимите необходимые сервисы (PostgreSQL, Redis, Qdrant):
```bash
docker compose up -d
```

## 5. Работа с миграциями базы данных

### Создание новой миграции
При добавлении или изменении моделей в своем домене сгенерируйте файл миграции из каталога `backend`:
```powershell
uv run alembic revision --autogenerate -m "краткое_описание_изменений"
```

### Обязательная проверка сгенерированного файла
Автоматическая генерация не идеальна: инструмент может пропустить изменения типов, некорректно обработать значения по умолчанию или случайно сгенерировать удаление существующей таблицы при отсутствии импорта модели в `env.py`.

Перед применением откройте созданный файл в папке `migrations/versions/` и проверьте функции `upgrade` и `downgrade` (рекомендуется передать этот файл агенту с запросом проверить корректность миграции относительно моделей).

### Применение миграций
После подтверждения корректности примените изменения к базе данных:
```powershell
uv run alembic upgrade head
```

В случае необходимости отката последней миграции:
```powershell
uv run alembic downgrade -1
```

---

## 6. Запуск сервера разработки

Для запуска сервера с автоматической перезагрузкой при изменении кода выполните:
```powershell
uv run uvicorn src.main:app --reload
```

После старта будут доступны:
- Проверка состояния: `http://localhost:8000/health`
- Автоматическая документация интерфейсов: `http://localhost:8000/docs`

---

## 7. Повседневные команды разработчика

Все команды внутри `backend/` выполняются через префикс `uv run` — это избавляет от необходимости вручную активировать виртуальную среду:

| Действие | Команда |
|---|---|
| Запуск всех тестов | `uv run pytest` |
| Проверка кода линтером | `uv run ruff check` |
| Автоматическое исправление стиля | `uv run ruff check --fix` |
| Форматирование кода | `uv run ruff format` |
| Создание новой миграции | `uv run alembic revision --autogenerate -m "описание"` |
| Добавление рабочей библиотеки | `uv add название_пакета` |
| Добавление библиотеки для тестов | `uv add --dev название_пакета` |
