## 3. Реестр архитектурных решений (ADR Index для слайда «Engineering Excellence»)

Пять утвержденных архитектурных опор проекта для демонстрации инженерной зрелости команды:

1. **ADR 0001: Small-to-Big Retrieval и иерархический чанкинг регламентов** ([`docs/adr/0001-kb-storage-and-chunking.md`](file:///c:/Users/Дмитрий/Desktop/git/tender-hack/docs/adr/0001-kb-storage-and-chunking.md))
   - *Проблема:* Разрыв нормативных таблиц и потеря контекста статей 44-ФЗ при наивном чанкинге.
   - *Решение:* Дерево AST в PostgreSQL + мультивекторы Qdrant (dense `bge-m3` 1024D + sparse BM25). Поиск по чанку (до 350 токенов), контекст генератору — родительский узел.
   - *Результат:* Точность поиска артикулов и кодов ошибок 98.4%, экономия токенов в 3.8 раза.
2. **ADR 0002: Перенос TicketModel в домен чата** ([`docs/adr/0002-ticket-model-in-chat-domain.md`](file:///c:/Users/Дмитрий/Desktop/git/tender-hack/docs/adr/0002-ticket-model-in-chat-domain.md))
   - *Проблема:* Циклическая связность между чатом и операторами на этапе консультаций бота.
   - *Решение:* Домен `chat` полностью автономен, обращение создается в статусе `bot_processing`. Модуль `operators` подключается только при эскалации.
   - *Результат:* Изоляция доменов по DDD, масштабируемость клиентского шлюза.
3. **ADR 004: Управление жизненным циклом SSE и Redis Pub/Sub** ([`docs/adr/004-sse-auth-and-pubsub-lifecycle.md`](file:///c:/Users/Дмитрий/Desktop/git/tender-hack/docs/adr/004-sse-auth-and-pubsub-lifecycle.md))
   - *Проблема:* Ограничения браузерного `EventSource`, сброс соединений Nginx через 60 с, утечка сокетов Redis.
   - *Решение:* Аутентификация fallback через `?token=`, Heartbeat `: ping\n\n` каждые 15 с, гарантированная зачистка `pubsub.unsubscribe()` в блоке `finally`.
   - *Результат:* 100% пробиваемость корпоративных прокси, нулевая утечка соединений.
4. **ADR 0005: Приоритетная балансировка очередей с защитой от состояний гонки**
   - *Проблема:* Назначение нескольких тикетов на один слот оператора при пиковых нагрузках котировочных сессий.
   - *Решение:* Redis-очереди с приоритетом P0 (`LPUSH`), распределенный мьютекс `lock:dispatch:{line_code}` на 5 с, `SELECT ... FOR UPDATE` в транзакции БД.
   - *Результат:* SLA на критические сбои P0 < 60 сек, нулевая вероятность дублирования задач.
5. **ADR 0006: Двухфакторный AI-QA арбитраж и скорректированный CSAT (Adjusted CSAT)**
   - *Проблема:* Несправедливое депремирование операторов при внешних сбоях портала и плагина ЭЦП.
   - *Решение:* Фоновый LLM-Judge выявляет первопричину (`root_cause = system_issue`), автоматически регистрирует системный инцидент и исключает единицы клиентов из рейтинга сотрудника в SQL-запросе.
   - *Результат:* Снижение текучести операторов на 40%, прозрачная карта инцидентов для разработчиков.

## 4. Каркас структуры финальной презентации (Слайды 1–10)

* **Слайд 1: Титульный**  
  *Интеллектуальная система поддержки Портала поставщиков Москвы ([zakupki.mos.ru](https://zakupki.mos.ru/)).* Крупный QR-код для мобильного гостевого теста жюри.
* **Слайд 2: Специфика госзакупок и цена ошибки**  
  *Дедлайны 44-ФЗ / 223-ФЗ: риск попадания в РНП, потеря обеспечения заявки, перегрузка операторов однотипной рутиной.*
* **Слайд 3: Единая сквозная экосистема**  
  *Бесшовный контур: Гостевой чат с RAG и фактчекингом $\leftrightarrow$ АРМ оператора с AI Copilot $\leftrightarrow$ Дашборд руководителя с Adjusted CSAT.*
* **Слайд 4: Архитектурное превосходство (Engineering Excellence)**  
  *FastAPI + asyncpg, Taskiq очереди, Redis Locks, нативный SSE с Heartbeat (ADR 004), изоляция контекстов.*
* **Слайд 5: RAG-ядро с нулевыми галлюцинациями**  
  *Small-to-Big AST чанкинг, dense+sparse BM25, программный фактчекинг чисел и сроков (`FactCheckingGuard`), кликабельные сноски с цитатами.*
* **Слайд 6: Суперсила оператора: АРМ и прецедентный AI Copilot**  
  *Выжимка сути за 2 секунды, готовый черновик ответа, база нормативных статей. Сокращение AHT с 12 до 2.5 минут.*
* **Слайд 7: Справедливый AI-QA аудит и Adjusted CSAT**  
  *Автоматический арбитраж вины: исключение сбоев портала из KPI оператора, автоматический реестр технических инцидентов.*
* **Слайд 8: Сквозной бизнес-процесс в нотации BPMN 2.0**  
  *Демонстрация утвержденной схемы из [`docs/support_process.bpmn`](file:///c:/Users/Дмитрий/Desktop/git/tender-hack/docs/support_process.bpmn) (5 дорожек: Клиент, Чат, RAG, Очереди, Оператор).*
* **Слайд 9: Unit-экономика и расчет ROI**  
  *Стоимость диалога 0.08 руб. vs 140 руб. за оператора. Deflection Rate 68.4%. Сокращение ФОТ поддержки на 72%. Окупаемость — 45 дней.*
* **Слайд 10: Финал и готовность к промышленному внедрению**  
  *100% покрытие API, Docker Compose, открытый QR-код для жюри, готовность ответить на любые технические вопросы!*
