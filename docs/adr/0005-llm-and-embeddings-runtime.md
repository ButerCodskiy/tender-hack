# ADR 0005: Двухузловой контур инференса LLM, локальные эмбеддинги bge-m3 и отказоустойчивость RAG

* **Статус:** Принято (Accepted)
* **Дата:** 2026-09-12
* **Домен:** `backend/src/core/`, `backend/src/kb/`, `backend/src/rag/`
* **Спецификации:** [docs/RAG_AND_PARSING_SPECIFICATION.md](../RAG_AND_PARSING_SPECIFICATION.md), [docs/DEFENSE_ROADMAP.md](../DEFENSE_ROADMAP.md), [docs/BACKEND_ARCHITECTURE.md](../BACKEND_ARCHITECTURE.md)

---

## 1. Контекст и проблематика (Context)

В ходе стресс-аудита готовности к защите хакатона выявлен ряд критических ограничений:
1. **Аппаратные ограничения демонстрационной машины:**
   Основной ноутбук (AMD Ryzen 7 5700U, 8 ядер, 16 ГБ RAM) оснащен интегрированным видеоядром Radeon Graphics без поддержки Nvidia CUDA. Локальный запуск моделей класса 7B на CPU в Docker дает низкую скорость (5–8 токенов/сек) и создает риск исчерпания оперативной памяти под нагрузкой.
2. **Наличие GPU-узла в команде:**
   В распоряжении команды имеется второй ноутбук с дискретным видеоадаптером **Nvidia GeForce RTX 4060 (8 ГБ VRAM)**, способный выдавать 50–70 токенов/сек при полном переносе весов модели в видеопамять.
3. **Статусы и текущее состояние кодовой базы:**
   - Модуль `backend/src/core/llm_client.py` являлся пустой заглушкой.
   - Генератор `backend/src/rag/generator.py` работал через `MockLlmStreamClient` с захардкоженным статическим текстом.
   - Модуль `backend/src/kb/qdrant.py` использовал `EmbeddingStub` (псевдовектора на базе хэш-сумм символов вместо эмбеддингов).
   - Каталог `backend/storage/kb_documents/kb_export/markdown/` содержит 7 боевых регламентов от организаторов (~2 МБ нормативного текста), однако индексация в PostgreSQL AST и коллекцию Qdrant не выполнялась.

---

## 2. Архитектурное решение (Decision)

### 2.1. Двухузловая топология развертывания (Dual-Machine Inference Topology)

Принято решение разделить вычислительные контуры:
1. **Узел приложений и данных (Host A — Текущий ноутбук):**
   - FastAPI Backend (API, Chat, RAG, WebSockets, SSE).
   - Docker Compose: PostgreSQL (реляционное хранилище AST), Redis (Pub/Sub и блокировки), Qdrant (векторный поиск).
   - Локальная генерация эмбеддингов (CPU/ONNX) для автономной индексации базы знаний.
   - Frontend (React + Vite, Fast Role Switcher).
2. **Узел генеративного инференса (Host B — Ноутбук с RTX 4060):**
   - Ollama Server (`OLLAMA_HOST=0.0.0.0:11434`), доступный по локальной Wi-Fi/Ethernet сети команды или мобильной точке доступа.
   - Модель генерации: семейство Qwen (`qwen 3.5 4b` / `qwen 2.5 7b-instruct`).
3. **Сетевое сопряжение:**
   - Адрес задается переменной окружения `OLLAMA_BASE_URL` (по умолчанию `http://localhost:11434`, для демо переопределяется на `http://192.168.X.X:11434`).
   - На Host A реализуется асинхронный клиент `OllamaStreamClient` с использованием `httpx.AsyncClient`, поддерживающий streaming через SSE / NDJSON (`/api/chat`).

---

### 2.2. Архитектура эмбеддингов и векторного поиска (Autonomous Embeddings Pipeline)

Чтобы процесс индексации нормативных документов не блокировался доступностью Host B:
1. **Dense-векторы (1024D):**
   - Вычисляются на Host A с использованием `BAAI/bge-m3` через `transformers` / ONNX с нормализацией $L_2$.
   - Схема коллекции Qdrant: `"dense": VectorParams(size=1024, distance=Distance.COSINE)`.
2. **Sparse-векторы (BM25 Lexical Hashing):**
   - Токенизация текста с очисткой от стоп-слов, подсчетом TF (term frequency) и хэшированием токенов в диапазон индексов `[1..30000]` с логарифмическим весом.
   - Схема коллекции Qdrant: `"sparse": SparseVectorParams()`.
3. **Слияние результатов:**
   - Двухканальный гибридный запрос через `models.FusionQuery(fusion=models.Fusion.RRF)`.

---

### 2.3. Паттерн отказоустойчивости (Graceful Degraded Mode)

Для исключения срывов на защите при сбоях Wi-Fi:
1. `OllamaStreamClient` оборачивается таймаутом соединения (3.0 сек) и таймаутом первого токена (5.0 сек).
2. При недоступности Host B генератор `RagStreamGenerator` не падает с ошибкой 500, а автоматически эмитит событие `RagDegradedModeEventSchema`:
   - Формирует ответ на базе наиболее релевантных найденных фрагментов базы знаний (Direct Citation Extract).
   - Сохраняет кликабельные сноски `[^1]`, ссылки на регламенты и статус `degraded: true`.

---

## 3. Последствия (Consequences)

### Положительные:
- **Скорость стриминга:** 50–70 токенов/сек на защите за счет RTX 4060.
- **Честная RAG-система:** Полное устранение mock-заглушек в пользу реальных векторов `bge-m3` и генерации Qwen.
- **Автономность индексации:** Индексация документов и наполнение Qdrant выполняются на локальной машине независимо от сети.
- **Отказоустойчивость:** Любые сбои сети второго ноутбука не приводят к белому экрану или аварийному завершению демо.

### Ограничения и риски:
- Требуется нахождение обоих ноутбуков в одной подсети (Wi-Fi или точка доступа смартфона).
- Службу Docker Desktop на Host A необходимо запускать с правами пользователя Windows перед стартом контейнеров.
