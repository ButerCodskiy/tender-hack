## 1. Контекст и Проблематика (Context & Problem)

Текущая реализация поиска в RAG осуществляет поиск по векторной базе Qdrant, извлекая мелкие чанки (`kb_chunks`), которые в `reranker.py` группируются по `node_id` через эвристическую формулу:
$$S_{\text{parent}} = S_{\max} + 0.10 \cdot \ln\left(1 + \sum S_i\right)$$
Однако при этом:
1. **Отсутствует подтягивание полного контекста (Small-to-Big)**:
   В генератор LLM передаются только тексты найденных мелких чанков, склеенные между собой, вместо полноценной родительской статьи/раздела (`kb_nodes.full_content`). Это приводит к фрагментарности юридического контекста (например, чанк содержит исключение, но родительское общее правило осталось за пределами выдачи).
2. **Отсутствует интерактивная навигация на Frontend**:
   Пользователь в интерфейсе видит плашки источников, но не может нажать на них, чтобы перейти к родительскому документу с визуальной подсветкой места, где именно этот фрагмент был взят.
3. **Вопрос рендеринга (PDF vs Markdown / Rich Text)**:
   Необходимо определить оптимальный формат представления для интерфейса оператора/пользователя: тяжелый рендеринг PDF (с canvas/PDF.js и Bounding Boxes) против легковесного адаптивного рендеринга Markdown-узла с подсветкой попадания.

## 2. Анализ текущего состояния инфраструктуры и схемы данных

1. **PostgreSQL для родительских чанков**:
   - **Схема существует**: В `src/kb/models.py` объявлена таблица `kb_nodes`, которая содержит полное тело родительского узла (`full_content: Text`), заголовок (`title`), структурный путь (`section_path`), таблицы в Markdown (`table_md`), а также ссылку на родительские узлы (`parent_node_id`).
   - Таблица `kb_chunks` содержит внешний ключ `node_id REFERENCES kb_nodes(node_id)`.
   - **Физический статус**: Локальный сервис PostgreSQL развернут в системе (`start_all.ps1` -> `postgres.exe` на порту 5432, данные в `C:\ProgramData\pg_data`).
2. **Qdrant и ссылки на родительские чанки**:
   - **Ссылки присутствуют**: В `src/kb/tasks.py` при индексации в payload каждой векторной точки записывается:
     ```python
     payload = {
         "doc_id": doc_model.doc_id,
         "node_id": c.node_id,  # Прямая ссылка на primary key kb_nodes!
         "regime": doc_model.regime,
         "has_table": c.has_table,
         "status": "ACTIVE",
         "kb_type": "guide",
         "kind": "chunk",
     }
     ```
   - Таким образом, Qdrant уже хранит детерминированную связь каждого атомарного чанка с родительской статьей `kb_nodes.node_id`.

## 3. Архитектурное решение (Decision)

### 3.1. Двухуровневый конвейер Small-to-Big Hydration

```
[Пользовательский запрос]
         │
         ▼
[1. Qdrant: Hybrid Search (Dense 1024D + Sparse BM25)]
         │  (Извлекает 15-20 малых чанков, высокий Recall)
         ▼
[2. Reranker: Weighted RRF (k=60) + Dynamic Cross-Encoder]
         │  (Отсекает шум, оставляет 4-6 лучших чанков с их node_id)
         ▼
[3. Parent Hydration Service (PostgreSQL)]
         │  Batch SQL: SELECT node_id, title, section_path, full_content, table_md
         │             FROM kb_nodes WHERE node_id = ANY(:node_ids)
         ▼
┌────────────────────────────────────────┬────────────────────────────────────────┐
│ Для LLM-генератора:                    │ Для Frontend / SSE Stream:             │
│ Передается родительский full_content   │ Передается RagSourceChunkSchema        │
│ (или усеченный до 800 токенов)         │ с parent_full_content, quote_text,     │
│ с сохранением структуры статьи.        │ title, section_path и highlight_range. │
└────────────────────────────────────────┴────────────────────────────────────────┘
```

### 3.2. Архитектура интерактивного Frontend: Rich Markdown Drawer с подсветкой

Вместо тяжелого PDF-viewer (который требует скачивания многомегабайтных PDF, сложен в мобильной верстке и не поддерживает чистый темный режим) принимается **Гибридный подход (Rich Text Drawer + Ссылка на источник)**:

1. **Интерактивные чипы источников (Source Badges)**:
   Под сообщением ассистента выводятся компактные кликабельные плашки:
   `[📄 Ст. 93 44-ФЗ: Закупка у ед. поставщика]`
2. **Шторка просмотра (Document Inspection Drawer / Sheet)**:
   При клике на плашку справа выдвигается боковая панель с полным текстом статьи (`kb_nodes.full_content`).
3. **Визуальная подсветка попадания (Highlighting)**:
   - Найденная цитата (`quote_text`) или диапазон символов в родительском тексте автоматически оборачивается в компонент `<mark>` с мягким акцентным градиентом.
   - Срабатывает плавный автоскролл (`scrollIntoView({ behavior: 'smooth', block: 'center' })`) непосредственно к найденному пункту.
4. **Кнопка первоисточника**:
   В шапке шторки отображается ссылка `source_url` (например, на zakupki.mos.ru или локальный PDF-файл в `storage/kb_documents/`), если пользователю требуется юридически заверенный оригинал.

## 4. Сравнение альтернатив

| Критерий | Альтернатива 1: Только мелкие чанки (Текущее состояние) | Альтернатива 2: Полный PDF Viewer (react-pdf / canvas) | Альтернатива 3 (Выбрано): Small-to-Big + Rich Markdown Drawer |
| :--- | :--- | :--- | :--- |
| **Качество ответа LLM** | Среднее (контекст фрагментарен) | Высокое (полный документ) | **Максимальное** (полная статья в контексте) |
| **Скорость загрузки Frontend** | Мгновенная (<50ms) | Медленная (1-3 сек на парсинг PDF в браузере) | **Мгновенная (<50ms)** |
| **Точность навигации** | Нет навигации по статье | Сложный расчет координат Bounding Box | **Точный скролл к цитате в DOM** |
| **Адаптивность / Dark Mode** | Базовая | Плохая (сканы/PDF не инвертируются нативно) | **Идеальная поддержка тем и мобильных устройств** |
| **Нагрузка на сеть** | Минимальная | Тяжелая (передача файлов PDF) | **Минимальная (JSON payload)** |

## 5. План миграции

1. **RAG Service (`backend/src/rag/service.py`)**:
   Добавить этап гидратации: после реранкинга вызывать `KbRepository.get_nodes_by_ids(node_ids)` и обогащать `RagSourceChunkSchema` полями `parent_full_content` и `highlight_offset`.
2. **Контроль контекстного окна**:
   Если статья превышает лимит (например, >1500 токенов), брать окно вокруг найденного чанка (`quote_text` $\pm$ 500 символов).
3. **Frontend (`frontend/src/components/chat/`)**:
   Создать компонент `SourceViewerDrawer.tsx` с поиском подстроки `quote_text` внутри `parent_full_content` и рендерингом через `react-markdown`.
