# Генерация названия Git-коммита

## Алгоритм анализа

1. **Найди точку отсчета**: 
   - Просмотри историю чата. 
   - Если в текущей сессии уже был вызов `/commit-name`, анализируй только те изменения, которые обсуждались **после** этого момента.
   - Если это первый коммит в сессии, анализируй весь контекст текущего диалога.

2. **Определи суть изменений**:
   - Какие файлы были изменены, созданы или удалены?
   - Какие задачи ставил пользователь и что было фактически реализовано?

## Шаги выполнения

### 1. Сформируй сообщение коммита

На основе анализа диалога создай сообщение коммита по формату:

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

**Типы коммитов:**
- `feat` — новая функциональность
- `fix` — исправление бага
- `docs` — изменения в документации
- `style` — форматирование, пробелы, точки с запятой (не влияет на код)
- `refactor` — рефакторинг кода без изменения функциональности
- `perf` — улучшение производительности
- `test` — добавление или исправление тестов
- `build` — изменения в системе сборки или зависимостях
- `ci` — изменения в CI/CD конфигурации
- `chore` — рутинные задачи, обновления зависимостей

**Scope (область):** указывай конкретный модуль/компонент, например:
- `auth`, `api`, `db`, `security`, `schemas`, `config`

**Примеры:**
- `feat(auth): add Google OAuth 2.0 login`
- `fix(db): resolve connection pool exhaustion`
- `refactor(api): extract user validation to separate service`
- `docs: update README with installation instructions`


## Примечания

- Сообщение должно быть на **английском языке**
- Используй повелительное наклонение: `add`, `fix`, `update`, а не `added`, `fixed`, `updated`
