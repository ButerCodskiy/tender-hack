# 03: Главный оркестратор сообщений и потоковый эндпоинт отправки с SSE

**What to build:** Реализовать главный конвейер оркестрации клиентских реплик в `ChatService.process_client_message` и потоковый эндпоинт `POST /api/v1/chat/messages`. При отправке вопроса клиентом сервис связывает реплику с активным тикетом со статусом `bot_processing` (или атомарно создает его), сохраняет сообщение клиента в PostgreSQL и оперативном контексте Redis, обращается к `RagService` и возвращает поток Server-Sent Events (`text/event-stream`). По завершении генерации ответ бота и источники нормативной базы знаний сохраняются в базу данных и Redis.

**Blocked by:** 01: Модели диалогов, обращений, линий поддержки и базовые репозитории, 02: Эндпоинт текущего состояния переписки и истории клиента

**Status:** done

- [x] Эндпоинт `POST /api/v1/chat/messages` защищен зависимостью `CurrentUserDep` и принимает валидированное тело `ClientSendMessageRequestSchema`.
- [x] При пустом тексте сообщения возвращается статус `422 Unprocessable Content`.
- [x] В `ChatService.process_client_message`:
  - Определяется постоянный чат клиента.
  - Извлекается активный тикет; при его отсутствии атомарно создается тикет со статусом `bot_processing` и приоритетом `P2`.
  - Сообщение клиента сохраняется в таблицу `messages` (`sender_type = 'client'`, `moderation_status = 'passed'`).
  - Сообщение сериализуется в JSON и сохраняется в списке Redis `chat:context:{ticket_id}` (`RPUSH`, `LTRIM -10 -1`, `EXPIRE 1800`).
  - Вызывается генератор `RagService.generate_answer(payload)` с передачей запроса клиента.
- [x] Эндпоинт возвращает `StreamingResponse` со спецификацией MIME `text/event-stream` и корректным форматированием SSE (`event: <type>\ndata: <json>\n\n`):
  - `event: status` (коды `classifying`, `searching`, `reranking`);
  - `event: sources` (список нормативных статей базы знаний);
  - `event: sentence` (сгенерированные предложения с флагом `verified`);
  - `event: done` (финальный текст ответа и агрегированная верификация).
- [x] По завершении генерации ответное сообщение бота сохраняется в таблице `messages` (`sender_type = 'bot'`), а ссылки на регламенты — в таблице `message_sources`.
- [x] Ответ бота добавляется в оперативный контекст Redis `chat:context:{ticket_id}` (`RPUSH`, `LTRIM -10 -1`, `EXPIRE 1800`).
- [x] Реализованы автоматические тесты: сквозной сценарий потоковой отправки сообщения, проверка структуры получаемых SSE-событий, валидация записей в PostgreSQL и ключей в Redis.
