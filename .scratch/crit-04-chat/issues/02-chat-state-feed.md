# 02: Эндпоинт текущего состояния переписки и истории клиента

**What to build:** Реализовать эндпоинт `GET /api/v1/chat`, возвращающий полное текущее состояние переписки аутентифицированного клиента: идентификатор чата, сводку активного обращения (если существует), до 50 последних сообщений ленты с источниками регламентов и флаги доступных клиенту действий (`can_escalate`, `can_cancel`, `can_feedback`, `feedback_ticket_id`).

**Blocked by:** 01: Модели диалогов, обращений, линий поддержки и базовые репозитории

**Status:** closed

- [x] В `src/chat/schemas.py` реализованы Pydantic-схемы `ActiveTicketSummarySchema` и `ChatStateResponseSchema` в соответствии со спецификацией API.
- [x] В `src/chat/service.py` реализован метод `ChatService.get_chat_state(user: UserModel)`:
  - Извлекает постоянный чат клиента (или создает его при первом обращении).
  - Находит активный тикет и формирует `ActiveTicketSummarySchema` (с именем назначенного оператора и кодом линии).
  - Извлекает до 50 последних сообщений ленты чата в хронологическом порядке.
  - Рассчитывает флаги `can_escalate` (доступно, если тикет в статусе `bot_processing`), `can_cancel` (доступно, если тикет в статусе `queued`), `can_feedback` (доступно, если последний закрытый тикет ожидает оценки).
- [x] В `src/api/v1/chat.py` зарегистрирован маршрут `GET /api/v1/chat`, защищенный зависимостью `CurrentUserDep`, возвращающий `ChatStateResponseSchema` со статусом `200 OK`.
- [x] При запросе без валидного Bearer-токена эндпоинт возвращает ошибку `401 Unauthorized`.
- [x] Реализованы автоматические тесты: проверка структуры ответа нового клиента (пустая лента, отсутствие активного тикета), проверка ответа при наличии активного тикета и сообщений, валидация прав доступа.
