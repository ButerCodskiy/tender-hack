# Спецификация: [CRIT-01] Базовые модели учетных записей, ролей и аутентификация по токенам

## 1. Цель
Реализовать минимально необходимый контур идентификации и аутентификации пользователей платформы в соответствии со спецификацией API (`docs/API_SPECIFICATION.md`) и схемой базы данных (`docs/DATABASE_SPECIFICATION.md`).

## 2. Основные требования
1. **Модели данных:**
   * Справочник системных ролей (`roles` / `RoleModel`): `client`, `operator`, `supervisor`, `admin`.
   * Реестр учетных записей (`users` / `UserModel`) с первичными ключами UUID7.
   * Профиль клиента (`client_profiles` / `ClientProfileModel`) с реквизитами организации и внешним ключом к `users`.
   * Создание постоянного диалога (`chats` / `ChatModel`) при регистрации клиента.
2. **Контур безопасности:**
   * Надежное хеширование паролей.
   * Генерация и валидация JWT: access-токен (срок жизни 15 минут) и refresh-токен (срок жизни 7 дней).
3. **Маршруты API:**
   * `POST /api/v1/auth/register` — регистрация клиента с созданием профиля и чата.
   * `POST /api/v1/auth/login` — аутентификация по email и паролю с выдачей пары токенов.
   * `POST /api/v1/auth/refresh` — обновление пары токенов по действующему refresh-токену.
   * `GET /api/v1/auth/me` — получение профиля текущего аутентифицированного пользователя.
4. **Централизованная зависимость:**
   * Единая зависимость проверки аутентификации в `src/api/dependencies.py` для защиты закрытых эндпоинтов.
