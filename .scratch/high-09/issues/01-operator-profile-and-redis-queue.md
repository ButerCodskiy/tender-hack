# 01: Профиль оператора, миграция базы данных и приоритетная очередь в Redis

**What to build:** Создание сущностей профилей операторов с контролем рабочих смен, лимитов слотов и привязки к линиям поддержки в PostgreSQL, а также сервис буферизации очередей обращений в Redis с соблюдением приоритетов.

**Blocked by:** None (can start immediately)

**Status:** closed

- [x] В PostgreSQL создана таблица `operator_profiles` со связью к пользователям и линиям поддержки, полями статуса смены (`active`, `break`, `offline`), ограничением слотов (`max_slots`) и временными метками фиксации разрыва связи и последнего назначения.
- [x] Подготовлена и успешно применена ревизия миграции Alembic для таблицы `operator_profiles` и индекса `idx_operator_profiles_dispatch`.
- [x] В слое доступа к данным реализован репозиторий операторов с методами создания, обновления статуса смены и выборки профиля.
- [x] В менеджере Redis реализованы методы постановки обращений в очередь конкретной линии `queue:line:{line_code}` с учетом приоритета: критические обращения P0 помещаются в начало списка (`LPUSH`), обращения стандартных приоритетов P1/P2 — в конец списка (`RPUSH`).
- [x] Реализованы методы извлечения тикета из начала очереди линии (`LPOP`) и проверки длины очереди.
- [x] Написаны тесты для проверки корректности сохранения профилей в базе данных и строгого порядка извлечения обращений разного приоритета из очереди Redis.
