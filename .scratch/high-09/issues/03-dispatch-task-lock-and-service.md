# 03: Фоновая задача распределения в Taskiq, распределенная блокировка и сервисный слой

**What to build:** Асинхронная оркестрация процесса распределения очереди линии через фоновую задачу Taskiq с распределенной блокировкой Redis для исключения параллельного исполнения.

**Blocked by:** 01: Профиль оператора, миграция базы данных и приоритетная очередь в Redis, 02: Балансировщик обращений, атомарный выбор оператора и шина событий

**Status:** closed

- [x] Определена Pydantic-схема полезной нагрузки задачи `DispatchPayloadSchema` с полями `line_code` и `trigger_reason`.
- [x] Реализован механизм распределенной блокировки `lock:dispatch:line:{line_code}` в Redis с временем жизни 5 секунд и гарантированным атомарным освобождением через Lua-скрипт по идентификатору воркера.
- [x] В сервисе операторов реализован метод `dispatch_line`, обеспечивающий цикл сопоставления: проверка очереди в Redis, извлечение тикета, вызов балансировщика, публикация события и корректное завершение при исчерпании свободных операторов или элементов очереди.
- [x] В очереди Taskiq `dispatch_queue` зарегистрирована фоновая задача `dispatch_line_queue`.
- [x] Реализованы сквозные интеграционные тесты: создание очереди с несколькими тикетами приоритетов P0, P1 и P2, наличие операторов с разным числом занятых слотов, запуск фоновой задачи и подтверждение назначения тикета P0 наименее загруженному оператору с корректным снятием блокировки.
